### Worktree, base, and environment
- **`git rev-parse --git-dir` returning a literal `.git` directory means you were dispatched into a LIVE checkout** — it happened 15 times in the first 24 dispatches (live outer repo, live ClarkHarness, live KryptonPay, all three variants). (dispatches 1–7; D15/D16/D17; D36 "fourteenth time")
- **Check the OVERLAP, never the head.** The live head moves mid-dispatch routinely; `git diff --stat <base>..<head> -- <your files>` empty means bundle from base and let the merge gate merge. Diff against the SHA you merged, never a branch name — a moving branch lies about your own deletions. (D16 onward; HW3)
- **A stacked dispatch names a FROZEN base SHA and the lower branch is held still, or the two dispatches are serialized.** Chasing a branch that is still committing restarts your whole verification stack on an unmeasured tree — fix your base and stop. (HW3, adopted as a chair rule)
- **Commit at part boundaries, always.** A usage-limit cut, API outage, or host death loses only what is uncommitted — D38 lost its report to four 529s and lost zero work because six commits sat in the worktree. (D7; D38; D42)
- **The ClarkHarness venv is `ClarkHarness/venv`, NOT `.venv`** — the only Python with psycopg/fastapi. There is no `master`/`main` head worth targeting: the real branch is `claude/krypton-fund-agentic-j8r2mu` (`main` is the LICENSE-only initial commit). (D13; D15)

- **Never run `next build` beside a live dev server** (clobbers `.next`, every route 500s — looks exactly like a regression; fix `rm -rf .next` + restart after killing ALL PIDs on the port). Two dev servers on one clone share `.next` and serve each other stale CSS — run ONE. (dispatch 3; D5; D31)

### Absence, controls, refusals (design rules with teeth)
- **`x or 0` and `float(x or 0)` are the absence-as-zero non-negotiable in miniature** — and the inverse matters equally: absence INSIDE a complete fold is a measured zero; absence OF the fold is not. A sum with an unknown term is UNKNOWN. Any new rule with an optional input must join `UNEVALUATED_ON_ABSENT` or it erases itself. (D17; ENG1 hot carries the pair)
- **A gate returns a VERDICT, never raises** — every read of a stored sub-payload needs the presence-AND-numeric-type guard (`int("ten")`, `int(None)`, `True`-as-1.0 are all live paths); this was reintroduced twice after being fixed once, both times caught outside the suite. (D23; D36; D37)
- **A threshold is not an off-switch** (an unmeasurable statistic refuses at ANY level — disabling needs an explicit boolean with `applied` in the verdict); **a flag that can only report one value is a decoration** (construct the input that makes it True before shipping); **a criterion shipped permanently unclearable looks like rigour.** (D36; D29)
- **A LIMIT on a control's backing query is a silent off-switch**: fetch `limit + 1`; the CONTROL raises on truncation, the DISPLAY reports rows + truncated + shown/total; publish the window edges (`/fund/events` serves the NEWEST 1000, so `events_scanned: 1000` is a lower bound wearing a total's name, and an old seq is invisible through that door). (validator carry; D24; HW1; HW3)
- **When two structures must agree, DERIVE one from the other** — a matching test is the weaker fix; name every deliberate difference and pin the difference set exactly. **A guard's scope is derived from a declaration in each guarded thing** — a maintained tuple has a silent off-switch. **A rule and the guard that decides whether the rule ran must not each carry the question.** (D18; D27 EVOLVE)
- **When you add an EventType you have changed a lifecycle until proven otherwise** — grep every fold that gates on aggregate_type and filters by allowlist/exclusion, and state in the diff which you checked (AutopolicyDeclined made orders un-approvable). Any diff changing a projection `_apply`'s semantics states what happens to snapshots folded under the old one. (adversary D17/D18 carries)
- **"Audible" means IN THE EVENT LOG, never `logger.warning`** — if a comment says a control must be observable, the fix appends an event. **A guard's returned attribution string is the EVENT's actor**, not a payload nicety. **Every new refusal on an approval path records like the ones already there.** (riskofficer/validator carries)
- **A loosening that also removes or moves a control is never the builder's to apply** — even when the brief asks and the measurements support it: build it, measure it, render it, file it with the numbers, leave the flip to a human. Separate counting from control existence — one flag doing both nearly removed the CEO's approve button. (D39, cited into the chair's own protocol)
- **A control that refuses correct work is not stricter; it is broken** (the redecision guard broke the ordinary two-decision lifecycle and passed 57 tests because none walked the whole lifecycle). **A rounded field is not a sort key** — sort on the raw instant with an id tiebreak; a total order or it is not an order. (HW3)
- **A correction that can only remove is half a correction** — split the halves in the payload and let the conjunction carry the claim (membership closes look-ahead; it cannot close survivorship when the dead have no prices). (D19)
- **Append-only stores: hash the rstripped text, store the verbatim, keep the ordinal in the key** — appending changes the PREVIOUS section's bytes, and this very file holds five sections named exactly `## STATE`. When you assert a decomposition loses nothing, assert the COUNT separately from the concatenation. (D27 + EVOLVE)
