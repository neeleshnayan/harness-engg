# The research funnel — operating rhythm

**v1, CTO + CEO, 2026-08-20. The honest starting point: two research artifacts
in the firm's life, both killed, quant never dispatched, alpha sleeve $0.
The kill machine works; this document is the generation machine.**

## 1. Throughput target and the arithmetic behind it

Target: **3–5 candidates entering the funnel per week**, sustained. Working
assumptions (estimates, to be replaced by measured base rates as cycles
complete): roughly a third of well-formed premia proposals survive blind
adversarial attack (the phenomenon is documented; implementations die on
specifics), and the belt/gate stage is power-limited more than truth-limited
until the history backfill lands. At those rates, 8–12 entrants ≈ 1–2
deployable premia strategies in 6–8 weeks. Every completed cycle updates these
numbers in a new section — the funnel measures itself or it is a hope.

## 2. The weekly cycle (dispatches are still explicit — cadence is a default, not a scheduler)

| day | dispatch | emits |
|---|---|---|
| 1 | **mechanism**, batched: next 3 unproposed/revivable PREMIA_MENU entries | 3 falsifiable proposals (or honest "not proposable, because…") |
| 2 | **analyst**: corpus sweep — local 4090 survey phase shortlists (checkable outputs only), Opus judges the shortlist | 0–2 theses; corpus-coverage note |
| 3 | **adversary**, batched, blind: the week's proposals + theses in one brief | KILL / SURVIVES / CANNOT TELL each, with revival conditions on kills |
| 4 | **quant**: survivors → LEAN, down the belt (hybrid draft flow's first real test) | implementations + gate verdicts, failures verbatim |
| 5 | **CTO**: resolve, file, update menu statuses + revival register; PM folds any deployable into book context | the week's funnel report on the desk |

One sub-agent in flight at a time still holds; the cycle is sequential by
construction. Costs at measured dispatch economics (~$0.70–1.00/dispatch on
Opus, batched): **~$5/week** — the CEO's stated posture is results first.

## 3b. Segment coverage — many analysts, one seat (CEO question, answered 2026-08-20)

A top firm's N analysts are N parallel attention streams with distinct
mandates and accumulated specialist knowledge. In this architecture the same
model plays every seat, so a "second analyst" would differ from the first only
by its brief and its memory — which we can already vary per dispatch. So:

- **One analyst seat, rotating SEGMENT MANDATES.** Each weekly dispatch
  carries a named segment (the band's biotech cluster; the guidance-cut
  cohort; the restructuring cohort; whatever the corpus's own density
  suggests). The seat's memory file accumulates per-segment sections, so
  segment knowledge compounds exactly as a specialist's would.
- **The 4090 survey phase IS the junior-analyst pool**: parallel local scans
  across segments cost nothing; Opus judgement is the scarce senior analyst
  and reads only the shortlists.
- **A specialist seat is FORKED only on demonstrated flow** — when one
  segment's mandate produces surviving theses repeatedly, it earns its own
  seat and memory file, per the roster rule. Coverage first, headcount when a
  segment proves it deserves one.

## 4. Funnel instrumentation (rendered, not implied)

The office already counts dispatches/verdicts/kills per day. Add to the weekly
funnel report: entrants this week, survivors per stage, cumulative
menu coverage (proposed / killed-with-conditions / live), and measured stage
base rates replacing §1's assumptions. A week with zero entrants is a RED
line in the report, not a quiet week.

## 5. What this rhythm refuses

No auto-scheduled agents (dispatches stay human-triggered; the cadence is a
default the CEO/CTO fire, and an idle week is visible). No lowering the gate
to feed the funnel — throughput comes from the top, never from the bar. No
strategy enters the book except through the unchanged chain.
