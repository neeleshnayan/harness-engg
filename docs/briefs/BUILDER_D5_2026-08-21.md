## E — Auto-resume for loss-class halts (ClarkHarness; CEO-approved policy, versioned)

A LOSS-class halt auto-resumes when ALL FOUR hold, evaluated on the
monitor tick: (1) the halt was explicitly ACKNOWLEDGED by the CEO (a new
guard-protected `acknowledge` action — same allowlist/echo mechanics as
the rebase, recordable without rebasing); (2) the triggering alarm no
longer evaluates true on current arithmetic; (3) no other critical alarm
is active; (4) a versioned cool-down has passed (constant, registered in
the judgement register with a written basis — propose a value with your
reasoning; the CEO decides it as part of accepting the diff).
**INTEGRITY and MANUAL halts NEVER auto-resume** — fail closed on any
ambiguity, including a halt with no class (pre-classes halts are treated
as integrity). The auto-resume writes a TradingResumed event whose payload
names the four conditions' evaluated values — an auto-resume nobody can
audit is an auto-resume that never should have happened. Tests: each
condition individually withheld keeps the halt; the classless case; the
audit payload.
