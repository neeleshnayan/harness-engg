## ARTIFACT 1 — d11_ch.patch (ClarkHarness): KILL

Not because the design is wrong. The core mechanism survives every attack run.
It is a KILL because three claims the artifact makes about itself are
demonstrably false, and two of those falsehoods point in the loosening
direction — a report reading safe when it is not.

### K1 — The "persistent, append-only" test ledger is the pytest scratch database

`app/fund/mode.py:37-44` promises: *"ISOLATED, NOT EPHEMERAL. `test` writes to
a persistent Postgres database, same schema, same append-only discipline...
a comparison needs both runs to still exist."*

`tests/test_pgstore.py:30` — `TEST_DB = "krypton_fund_test"`.
`tests/test_pgstore.py:70` — `cur.execute("TRUNCATE fund_events")`.
`tests/test_snapshot_firestore.py:84,101` — same database, same TRUNCATE.
Ten test modules gated on `SKIP_PG_TESTS` all target `krypton_fund_test`; the
diff touches none of them. DSN identity proven by running the patched
`pg_dsn_for(MODES[TEST], dsn())` against `test_pgstore._test_dsn()`:
**IDENTICAL: True.** The database exists now and holds pytest debris (4 events).

Consequences: every `pytest` run against a reachable Postgres truncates the
test-mode fund's whole event log — the mode's headline property is false from
the first run. And `tests/test_pgstore.py:24-29` itself says: *"A test that can
corrupt the ledger it is testing is not a test"* — this diff re-points a fund
ledger at exactly the database that comment was written to keep the fund away
from, bogus-hash insertion included. Additionally `tests/conftest.py:19,29`
means a shell with `FUND_STORE=postgres` exported makes the ENTIRE suite write
into the test fund's ledger, not just the 10 PG modules.

### K2 — The exit-coverage report hides $324.60 of the $1,165 it was built to reveal

The implementation is `covered = {r.get("symbol") for r in rules}` — symbol
only. `active()` returns every rule with no filtering: superseded rules, rules
carrying `triggered_at`, rules carrying `overridden_at`, and rules belonging to
any other strategy all count as coverage. Against the live rule set and live
broker quantities:

```
REPORTED uncovered: MSFT/NVDA/SOFI/XLE            = $674.10
ACTUALLY uncovered: + SPY $166.74 + GLD $179.70 + INTC $144.90 = $1,165.44
SILENTLY CALLED COVERED:
  SPY  <- rules on sleeve_premia_equity, which will no longer hold it (K3)
  GLD  <- machinery-test loss_pct, ALREADY TRIGGERED 2026-08-20T08:01:26
  INTC <- machinery-test gain_pct + a SUPERSEDED wiring_verification rule
```

Reproduced INSIDE the patched `check()`: with the live GLD machinery-test rule
plus its `ExitRuleTriggered` on a synthetic post-sync book, GLD drops out of
`uncovered`. A dead rule scored as a live control, on precisely the positions
the block exists to make visible. Absence scored as a value, reintroduced
inside the fix for it. This is a loosening.

### K3 — `_apply_venue_reconciliation` strips strategy ownership from partially-released positions

The docstring documents RELEASE and ADOPT; the code has a third case: it
empties EVERY holder of the symbol, then writes any surviving quantity into
DISCRETIONARY. A position that was merely reduced changes owner. On the live
book, SPY 0.346119 → 0.217757 would leave `sleeve_premia_equity` holding
nothing — so autopolicy v3's "the rule's own strategy must hold the quantity
it sells" can never again be satisfied for SPY's exits (fails closed — safe,
but a control stops working silently), and the premia sleeve reports zero.

### K4 — `CashReconciled`: a NAV-moving fold with zero producers

Defined at `events.py:168`, folded at `nav.py:294` and `positions.py:151`
(`book.cash += delta`), emitted by NOTHING. And `positions.py:117-125`,
seventeen lines above, argues that its sibling event must be a SET because "a
delta re-applied would move the book twice" — `CashReconciled` is exactly that
delta, with no run_id, no idempotency check, no approval path.

### K5 — The two "independent locks" on alpaca-prod are both inert

`resolve()` at `mode.py:515` is `if mode is ALPACA_PROD and not allow_prod:` —
**`PROD_UNLOCKED` is not in the condition; neither are the five
preconditions.** `allow_prod=True` opens everything: `activate()`,
`pg_dsn_for()`, `build_connector()` and `EventStore.__new__` all accept the
prod spec unguarded — `build_connector` BUILT a live `AlpacaConnector(paper=False)`
in the probe. Prod is unreachable today by ABSENCE OF A CALLER, not by the
advertised mechanism. Worse: `prod_gate_report()["reachable"]` computes from
`PROD_UNLOCKED`, so it can read True while the code refuses — the report
measures the documented design, not the shipped line. And the upgrade hazard:
whoever eventually unlocks prod will flip the constant, observe nothing change,
and go edit `resolve()` — where deleting the `if` removes constant,
preconditions and the only real lock in one stroke. Also
`assert_connector_permitted` is a string comparison on a self-declared class
attribute: a mock class with `name = "alpaca"` was ACCEPTED.

### K6 — `venue_label` is never written anywhere

*"The label stamped on fills and submits"* — nothing stamps it. The pipeline
derives venue from `connector.name`, which is `"alpaca"` for both paper and
live. The distinct `"alpaca-live"` label exists in no event. `real_money` gates
nothing.

### K7 — The CEO's toggle bricks the next restart, invisibly

`scripts/run.sh` exports `FUND_MODE=alpaca-paper` unconditionally; the switch
endpoint writes only the file. Any UI mode switch guarantees `ModeConflict` on
the next restart. It fails closed — correct — but the failure lands at restart,
not at click, and the UI never renders `declared.env` vs `declared.file`.

### K8 — Two smaller falsified claims

The claim that `.env` carries `FUND_LIVE_MARKS=true` is false against the live
`.env` (no such key), so removing the hidden `or` DOES change behaviour for
anyone starting test mode outside `run_test.sh` (loud absence — safe direction,
wrong premise). And `.env.example` removes `ALPACA_PAPER=true` claiming the
switch is gone; `connectors/alpaca.py:79` still reads it.

## ARTIFACT 2 — d11_kp.patch (KryptonPay): SURVIVES, one repair

Additive, merges cleanly onto `731354e3`. Handles the split-merge case
correctly: UI without the spine renders **MODE UNKNOWN — alarming**, never a

## What would change the verdict

K1: point test mode at a database no test file names (e.g. `krypton_fund_dev`)
or move the ten PG test modules off it. K2: key `covered` on
`(strategy_id, symbol)` filtered on not-superseded / not-triggered /
not-overridden. K3: a docstring case for partial release plus a decision on who
owns the survivor. K4: an emitter with a run_id and an approval path, or delete
both folds. K5: put `PROD_UNLOCKED` and the precondition check INSIDE
`resolve()`'s condition; make `allow_prod` private/test-only; gate `activate()`
and `build_connector()` on the same report. K6: stamp `venue_label` or delete
the field. K7: the switch endpoint refuses or loudly warns on an env/file
conflict; render both declarations in ModeBar. KP: a `default:` branch at
volume alarming plus a test feeding a fourth value.

**"Nothing here argues against the design... I would expect a v2 carrying
K1–K4 to survive."**
