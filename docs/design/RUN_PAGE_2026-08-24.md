# The run page — lineage made clickable (CEO instruction 2026-08-24)

CEO, verbatim: *"say a specific finding triggered a build then I should be
able to click on it, go to that desk and understand what they were doing,
how the found it, wht the ask was, what it unblocks etc"* — ratified via
the session mockup. Third of the window specs (REQUEST_CARD, SEAT_CARD).

## The principle

A lineage chip is a DOOR, never decoration. Every run gets a canonical
page (`/studio/desk/runs/{run_id}`); every request gets one too. Lineage
is BIDIRECTIONAL: upstream (what fired this) and downstream (what this
unblocked — anything whose filings, dispositions, or serves_requests cite
this run, resolved from the log at read time).

## The run page's five zones

1. **Header** — seat, run name, verdict one-liner; the metadata line
   (date · duration · tokens · id) in small muted type.
2. **Triggered by** — the upstream chip chain, each chip opening that
   record (a run, a request, a CEO instruction quoted from the approval
   event). "Lineage undeclared" rendered honestly for old rows.
3. **What they did, and how they found it** — the narrative paragraph
   (from the run's output/verdict), plus artifact links: the filed doc,
   kept probes, external sources cited.
4. **The asks it filed** — each recommendation with its CURRENT
   disposition state (open / accepted / done · citation / deferred),
   folded live from the desk, so the page never goes stale.
5. **What it unblocked** — downstream chips: dispatches, merges,
   decisions, binds-sent that cite this run.

## THE SPEND-DEMOTION RULE (CEO correction, same session, verbatim)

*"this puts the spend on my focus lens; I am more interested in the work
being done. this can be a small mention per ticket not the focus."*

Binding on ALL window surfaces (request card, seat card, run page):
**the work is the face; the spend is a footnote.** No metric-tile rows on
cards. Tokens/cost render only as part of the small muted metadata line
(e.g. "2026-08-24 · 25m · 242k tokens"). The SEAT_CARD spec's LEDGER zone
is AMENDED accordingly: the three-tile row is struck; a seat card carries
one quiet line ("today: 4 kills, 2 certs · 1.4M tokens") under the
header. Teamwide ROI remains Grace's surface — her memos and a dedicated
ledger view — never ambient chrome on work cards.

## Sequencing

Rides D40 with the seat card (after D39; shared surfaces). The downstream
resolver and the run-page projection are spine work
(`GET /fund/desk/runs/{run_id}/page` or equivalent); the asks' live
disposition fold reuses the desk's existing fold — no second source of
truth.
